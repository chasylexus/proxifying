# Короткий маршрут работы

Общие инструкции действуют без изменений. Здесь — карта проекта, чтобы не повторять широкое исследование при каждой доменной правке.

## Правила и потребители

- Канонический список T: `surge.ruleset.proxy-t.list`. Запись `DOMAIN-SUFFIX,example.com` покрывает корень и поддомены. Для A и DIRECT есть соседние `surge.ruleset.proxy-a.list` и `surge.ruleset.direct.list`.
- Обёртки macOS/iOS используют внешние списки. Обычное добавление домена не требует менять обёртки, собирать большой профиль или переформатировать списки.
- Для запроса «во всех репозиториях» сначала используй карту; повторный поиск всех репозиториев нужен только при изменившемся составе.

| Репозиторий | Источник правил T |
|---|---|
| proxifying | `surge.ruleset.proxy-t.list` |
| shadowrocket-proxifying | `shadowrocket.ruleset.proxy-t.list` |
| throne-routing-data | `rule-set/manual-t.json`, массив `domain_suffix`; формат JSONC |
| trust-tunnel-routing-data | `vpn.txt`: отдельно корень и `*.домен`; актуализировать `vpn_domains` в `stats.txt` |
| openwrt-xray-router | Активная конфигурация получает Throne `manual-t`; править роутер для добавления домена не требуется |

Trust Tunnel объединяет T+A: конкретный туннель выбирает клиент. Репозитории движков и мостов обычно используют чужие списки; сначала установи владельца правила. Архивы и примеры меняй при соответствующем охвате задания.

## База и публикация

- Используй заданный пользователем SHA; иначе сверяй базу с удалённым `main` через `git ls-remote origin refs/heads/main`. Локальные `main` и `origin/main` могут устареть или иметь другую историю.
- Грязную рабочую копию сохраняй. Если её база расходится с удалённой, переноси только правку задания в отдельную чистую копию; не публикуй старый checkout целиком.
- Проверь effective identity и источники настроек одним пакетом. Метка `privacy.profile=general` не отменяет переопределения `user.*` и подписей в `.git/config`. Обязательные проверки перед commit/push сохраняются.
- Штатному `codex-git-release` нужны ветка `main`, подписанный HEAD и отсутствие unstaged tracked changes. Проверка подписи HEAD не означает требования переподписать всех предков. Переписывание истории требует отдельного запроса.

## Минимальная проверка

- Проверь точный diff, синтаксис, уникальность новых записей, корень/поддомены и соседние имена, приоритет T и сохранность прежних правил. Для Trust Tunnel сверь фактическое число доменных строк со счётчиком.
- Сборки движков, полный набор тестов и проверки всех URL не нужны для изменения двух доменных строк. Расширяй проверки при изменении контрактов или ссылок.
- Работающий Surge содержит отдельные приватные настройки: не выводи полный профиль. Найди точный ресурс через `surge-cli --raw external-resource list`, обнови только его `key` и проверь `surge-cli rule match <домен>`.
- Временные правила могут перекрывать внешний список. Успешный `rule match` сам по себе не доказывает обновление постоянного ресурса; проверяй также публикацию и состояние ресурса. Чужие временные правила сохраняй.
